# code-review

## 工作流程

1. 检查实际差异、主路径、现有契约与调用方，按 [组件目录](../../../docs/architecture/component-catalog.md) 找重复实现。
2. 检查参数与业务规则、异常映射、不可见的日志或泄漏、事务代理/回滚、SQL 性能、权限和兼容性。
3. 根据变更核对缓存一致性、消息保证、幂等、并发与故障恢复。把潜在回归对应到测试及残余风险。
4. 审查 [DoD](../../../docs/standards/definition-of-done.md) 和实际命令结果。

## 输出与验收检查

输出：按 P0～P3 列文件位置、触发条件、影响、修复和覆盖缺口。禁止以测试计划替代结果。验收：阻断问题皆有复验，未验证的范围已明确。
