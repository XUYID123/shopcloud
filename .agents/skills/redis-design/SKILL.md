# redis-design

## 工作流程

1. 读取 [Redis 现状](../../../docs/middleware/README.md) 和 [Redis ADR](../../../docs/decisions/0001-redis.md)。比较 MySQL 查询与缓存，明确安全域/缓存域及实际组件。
2. 给出 Key 命名空间、版本、数据结构、负值与正常 TTL、抖动、大小上限和淘汰影响。穿透用输入校验与负缓存，击穿用受控单键加载，雪崩用抖动和并发预算。记录热 Key、大 Key 发现和缓解。
3. 从业务提交追踪至更新/失效。审查并发回填、Redis 超时、重复删除、待执行积压和补偿，区分安全拒绝和 DB 回源。
4. 测试命中/空值/TTL、热点并发、原子操作、更新回滚、断开/恢复与补偿。

## 输出与验收检查

输出：必要性、Key/TTL、并发时序、故障策略、监控及证据。禁止将可淘汰缓存充当账本或将短窗口防重视为持久幂等。验收：容量、陈旧窗口和回源压力可解释。
