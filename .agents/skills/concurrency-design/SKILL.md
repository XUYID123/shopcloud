# concurrency-design

## 工作流程

1. 确定资源、所有者、原子边界及并发交错，区分相同请求重放和不同请求竞争。
2. 比较唯一约束、条件更新、版本 CAS、行锁、Redis 原子操作及分布式锁。库存写以 MySQL 约束和受影响行数为准；Redis 锁必须分析 lease 到期、锁主人检查与迟到写入。
3. 明确操作标识、请求指纹、重复返回、版本冲突、锁顺序、回滚、重试预算和消息重投。查 [数据库](../../../docs/database/README.md)及[商品并发 ADR](../../../docs/decisions/0003-product-concurrency.md)。
4. 用同步栅栏发起双方请求，断言库存下界、最终版本、唯一副作用和失效状态，覆盖一方超时、回滚及重放。

## 输出与验收检查

输出：不变量、竞态时序、原子性与冲突表、并发用例。禁止把应用内检查当作跨实例原子保障。验收：每次竞争都有可预期且可断言结果。
