# 数据库与消息一致性

采用 MQ 时覆盖事务回滚、业务已提交未发送、发送超时重发、消费已提交 ACK 丢失。现有 Redis 失效记录只用于缓存。

- **事务 Outbox**。业务和事件记录同事务提交，事件 ID 唯一。投递器有界认领、失败后退避、租约可恢复，收到发送确认后持久化状态。崩溃或确认丢失会重发，消费端须消重。记录重试次数、最近失败、下次投递和积压年龄，提供归档、补偿与受控重放。
- **RocketMQ 事务消息**。按版本验证 half message 与事务回查。由持久化业务结果决定提交/回滚，约定未知结果、回查上限和补偿流程。
- **消费事务**。用消费组和 eventId 唯一约束保证原子去重，提交后 ACK；业务失败时去重记录同回滚。重复成功时直接确认，乱序通过状态和版本防回退。外部副作用使用持久任务和下游幂等键。定义跨事件 ID 的业务幂等约束。
- **验收**。注入业务回滚、发送超时、投递进程终止、消费失败和提交后 ACK 丢失；比较 MySQL、投递表、消费状态和实际副作用次数。
