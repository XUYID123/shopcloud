# 用户注册实现与验收

修订日期：2026-10-15。当前完成的是用户注册；登录、JWT、刷新/退出、地址和网关治理按后续阶段实施。用户数据库由 shop-user/compose.yaml 管理，Flyway V1/V2 保持不变。

## 1. 代码阅读顺序

| 文件，路径相对于 shop-user/src/main | 职责 |
|---|---|
| java/org/spring/shopuser/entity/UserEntity.java | 映射 user_account；包含 passwordHash，不作为接口响应；密码哈希标记 JsonIgnore，且不生成包含密码的 toString |
| java/org/spring/shopuser/mapper/UserMapper.java + resources/mapper/UserMapper.xml | 按用户名/ID 查找、插入并获取数据库生成的 ID；参数使用 #{...} 绑定 |
| java/org/spring/shopuser/mapper/RoleMapper.java + resources/mapper/RoleMapper.xml | 查询启用的 USER 角色，事务内共享锁防止分配过程中被禁用；插入用户角色关系 |
| java/org/spring/shopuser/dto/UserRegisterRequest.java | 只接收 username/password；Jakarta Validation 校验；password 只允许反序列化 |
| java/org/spring/shopuser/vo/UserVO.java | 只输出 userId、username、roles；userId 使用字符串 |
| java/org/spring/shopuser/config/RegistrationConfiguration.java | BCrypt 编码器；JSON 数字/布尔值不隐式转为用户名或密码字符串 |
| java/org/spring/shopuser/service/UserService.java | 注册规则、哈希、数据库唯一冲突处理和本地事务 |
| java/org/spring/shopuser/controller/UserController.java | POST /api/v1/users；返回 HTTP 201、Location 和 common 的 Result |
| java/org/spring/shopuser/web/RequestIdFilter.java | 请求标识校验、响应头、MDC 写入与清理 |

common 继续提供 Result、ErrorCode、BusinessException、GlobalExceptionHandler。当前用户服务通过已有的 @Import 使用公共异常处理器，不复制实现。

## 2. 实际执行过程

1. Controller 接收请求；未知字段、错误 JSON 类型、缺少字段或非法值返回 400。
2. Service 预查询用户名，已有账号返回 409 USERNAME_EXISTS。
3. BCrypt 在数据库事务外编码密码，避免等待哈希时占用连接和锁。
4. TransactionTemplate 开启本地事务，读取并锁定启用的 USER 角色。
5. 插入 user_account，默认状态 ENABLED、token_version=0，由数据库生成 ID。
6. 插入 user_role，只有两次写入都成功才提交；角色不存在或不可用返回 503，关联失败则回滚用户记录。
7. 并发下预查询可能同时通过，最终以 MySQL 用户名唯一约束为准；插入产生 DuplicateKeyException 时转换为 409。
8. 返回 UserVO 和统一响应，不返回 password/passwordHash、内部状态或令牌版本。

注册不接受昵称、角色、权限、用户 ID 或状态字段。昵称等资料后续单独维护；普通注册永远关联服务端查到的 USER 角色，而不是信任客户端输入或硬编码某个 role_id。

## 3. 请求与响应

IDEA 重新加载 Maven，确保 Docker Desktop 正在运行，以 shop-user 为工作目录启动 ShopUserApplication。可打开 shop-user/requests/user-registration.http 发送请求。

```http
POST http://localhost:8081/api/v1/users
Content-Type: application/json
X-Request-Id: register-demo-001

{"username":"flour_demo_01","password":"FlourDemo123!"}
```

第一次注册返回 HTTP 201，并包含：

```http
Location: /api/v1/users/1001
X-Request-Id: register-demo-001
```

```json
{
  "code": "OK",
  "message": "操作成功",
  "data": {
    "userId": "1001",
    "username": "flour_demo_01",
    "roles": ["USER"]
  },
  "traceId": "register-demo-001"
}
```

ID 只是示例，以实际数据库生成为准。Location 标识新创建的用户资源，当前没有开放 GET /api/v1/users/{id}；不能由此推断匿名用户可以查询其他账号。

| 场景 | HTTP | code |
|---|---:|---|
| 注册成功 | 201 | OK |
| 用户名/密码不合法、JSON 格式或字段类型错误 | 400 | VALIDATION_ERROR |
| 提交 role、roles、permissionIds、status 等未声明字段 | 400 | VALIDATION_ERROR |
| 用户名重复，包括大小写变体 | 409 | USERNAME_EXISTS |
| 请求不是 application/json | 415 | UNSUPPORTED_MEDIA_TYPE |
| USER 默认角色不可用 | 503 | DEPENDENCY_UNAVAILABLE |
| 未知系统错误 | 500 | INTERNAL_ERROR |

错误 data=null，响应头请求标识与 traceId 一致；错误内容不回显密码或内部异常。全局处理器保留业务异常的实际 HTTP 状态，MVC 框架异常也包装为统一格式。

## 4. 公共返回格式调整

Result.code 从早期示例的整数改为接口契约中的字符串业务码，如 OK、VALIDATION_ERROR、USERNAME_EXISTS；HTTP 状态由 ResponseEntity 单独设置。增加 traceId。保留 BusinessException(String)、BusinessException(Integer,String) 和 Result.fail(Integer,String) 的调用入口以兼容已有示例，但它们输出的 JSON 也采用字符串业务码。

基于 RBAC 多角色关系，User 从单个 role 调整为 roles 数组。文字接口文档与 OpenAPI 已同步，注册使用独立 UserRegisterRequest schema，不再与登录请求共用命名。除注册外的其他 OpenAPI 接口仍标记为设计，不能当成已实现功能。

## 5. 测试覆盖与运行

本次清理构建后完整验证通过：45 项测试、0 失败、0 错误；其中注册接口集成测试 43 项，原有 schema 和 common 启动测试各 1 项。12 个并发重名请求实测为 1 个创建成功、11 个冲突，用户与角色关联各保留一份。OpenAPI 的 580 处本地引用校验通过。

从根项目执行 Maven：

```text
mvn -pl shop-user -am test
```

测试需要真实 Docker MySQL。集成测试使用随机 HTTP 端口和真实 MyBatis SQL，覆盖：

- 正常注册、生成 ID、BCrypt 校验、默认角色及只返回允许字段。
- 最大用户名长度、8/72 位密码边界，以及缺失、越界、非法字符、错误 JSON 类型等拒绝场景。
- 角色/权限/状态/ID 等字段注入，错误 JSON 与尾随 JSON。
- 密码不进入校验错误响应及日志，实体序列化不包含密码哈希。
- 用户名大小写判重；12 个并发 HTTP 请求只有一个 201，其余 409，只创建一个用户和一条 USER 关联。
- 默认角色不可用时不创建用户；模拟关联写入异常时，已经插入的用户记录回滚。
- 请求标识透传、非法标识重新生成，响应体与头部一致。

故障测试只替换当前测试进程的 RoleMapper 行为，不修改数据库中的公共角色配置。测试结束仅清理本测试生成的随机用户名及其关联，不清空业务表或重置数据卷。
