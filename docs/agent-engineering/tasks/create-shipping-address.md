# 收货地址接口

2026-11-21，按项目后续业务顺序交付 `POST /api/v1/addresses`。契约见 [用户与地址](../../03-接口文档.md#2-用户与地址)。

- MySQL REQUIRED。增量迁移创建 `user_address`。事务按用户主键锁定账号，再按 `(user_id, id)` 检查 20 条上限。明确请求默认地址时，按默认地址唯一索引取消旧默认后插入新地址。生成列唯一约束保证同一用户最多一条默认地址，插入失败回滚变更。未请求设为默认时尊重请求值。
- 参数、权限、日志和异常 REQUIRED。网关沿用动态 `address:write:own`，服务端从内部 JWT 取得用户 ID。USER 已有权限，ADMIN 增授相同的本人地址权限。请求以契约校验，地区来自服务配置，开发默认仅使用文档中的 `310115`。复用 Result、BizLog 和 Trace，日志只记录操作、用户和生成的地址 ID。
- Redis 与 RocketMQ NOT_REQUIRED。复用网关既有权限快照及 TTL，无地址缓存和消息。POST 遵循资源创建语义，事务失败可重试，已成功的请求重复发送会新建地址。
- 性能与验证 REQUIRED。验证真实 MySQL、本人归属、默认切换、并发达到上限、输入与身份拒绝。默认更新与查询都通过索引定位单个用户数据。

## 本机启用

启动新版 `shop-user` 后由 Flyway 执行 V5。地区配置在 `shop.address.regions`，键为六位行政区代码，值为地区名称。本地网关使用 [Enable-AddressRule.ps1](../../../infra/security/Enable-AddressRule.ps1) 追加缺失的 `address:write:own` 规则，沿用发布器的版本校验。已缓存的管理员权限按网关原有 TTL 刷新。

## 验收

- 在临时 MySQL 8.4.11 和两套 Redis 8.2.10 上执行 `mvn -o -pl shop-user -am test -Dspring.cloud.nacos.discovery.enabled=false -Dspring.docker.compose.enabled=false`。Flyway 从空库应用 V1 至 V5，公共模块 46 项、用户模块 66 项通过。四项地址集成测试覆盖响应字段、归属、默认切换、身份与参数拒绝、并发上限和插入失败回滚。
- 通过隔离网关实际注册、登录和创建地址。USER 和仅有 ADMIN 角色的测试账号都返回 201。无权限的已登录用户返回 403，匿名请求及缺少内部签名的直连返回 401。带其他用户 ID 头的请求仍按签名主体保存。网关、用户服务和业务日志共享 Trace ID。
- 网关验证使用静态服务发现和临时 RBAC 规则，上述测试进程及容器均已清理。OpenAPI 与本地发布脚本已通过语法检查。

## 查询、编辑和删除方案

- MySQL、参数、权限、异常、日志与验证 REQUIRED。列表在只读事务校验账号状态并读取本人地址，默认地址在前，其余按 ID 降序。编辑和删除沿用新增接口的账号行锁，通过 `user_id + id` 定位目标，缺失或非本人统一返回 404。地址 ID 沿用数据库生成的正整数。
- 完整替换复用现有请求校验和地区配置。设为默认时同事务取消其他默认地址，事务失败回滚。取消或删除默认地址后由用户选择新默认地址。删除范围为地址簿记录，已下单的地址快照独立保存。
- Redis 与 RocketMQ NOT_REQUIRED。网关规则继续要求 `address:write:own`，发布器仅追加缺失规则并沿用版本校验。重复提交相同的 PUT 得到同一地址表示，重复删除返回 404。验证空列表、本人排序、默认变更、越权拒绝、回滚和编辑与删除竞争。

### 查询、编辑和删除验收

- 在独立 MySQL 与 Redis 上复跑相同的 Maven 命令，公共模块 46 项、用户模块 70 项通过，其中 8 项为地址集成测试。查询了空列表、默认地址排序和编号类型。重复编辑同一地址返回同一资源，编辑失败恢复此前的默认地址。并发编辑与删除保留最终删除结果。
- 临时真实网关完成注册、登录和地址新增、列表、修改、删除。伪造用户头无法改变列表归属，跨账号编辑或删除返回 404，无权限和匿名请求分别返回 403 和 401。测试进程与容器已清理。
- OpenAPI 已标记三个接口为已实现，并记录请求、响应和权限。沿用 V5 地址表和索引。

## 订单读取收货地址方案

- 权限、参数、异常、日志与验证 REQUIRED。用户服务默认关闭该入口，启用时用订单服务的独立公钥验签。JWT 限定 `shop-order → shop-user`、`order:address:read`、GET、完整路径和原始查询串。仅接收单个十进制正整数 `userId`，并校验同格式的 `addressId`。日志沿用 Trace 与 BizLog，仅记录操作和地址编号。地址查询响应禁止缓存。
- MySQL REQUIRED。只读事务沿用 V5 表和索引，单次查询校验地址与用户的归属及账号状态。记录不存在、归属不符或账号停用统一返回 404。依赖暂时不可用返回 503。读取无写入副作用，签发新凭据后可安全重试。
- Redis、RocketMQ 与新迁移 NOT_REQUIRED。该接口提供下单时读取地址的能力，订单生成和快照持久化随结算流程实现。

### 订单地址查询验收

- 隔离 MySQL 8.4.11 和两套 Redis 8.2.10 上复跑同一 Maven 命令。公共模块 47 项、用户模块 75 项通过。新增测试覆盖原始查询串的绑定、旧库存验签协议、地址真实读写后的查询、归属及账号状态、重复参数、非法编号、错误响应禁止缓存和数据库故障 503。
- 使用独立测试密钥，直连真实用户服务读取地址返回 200，修改已签名的 `userId` 返回 401。使用已登录账号和相同服务凭据经过网关，两种路径均被拒绝。网关地址簿回归验收通过。核对业务日志包含地址 ID 和 Trace，测试进程、容器和临时密钥已清理。
- 网关联调使用本地静态服务发现。订单调用点及地址快照持久化将在下单流程接入。OpenAPI 已标记该地址接口为已实现。
