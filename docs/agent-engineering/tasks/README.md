## 记录内容

每份记录可按以下字段组织。

- 任务 ID、需求摘要、主路由、授权边界、复杂度、风险、当前阶段、受影响模块及更新时间。
- 现状与复用证据，设计决策、相关 ADR、事务、异常日志、权限、并发和中间件判断。
- 每项评估记录 REQUIRED、NOT_REQUIRED 或 NEEDS_CONFIRMATION 及理由。未决事项保留阻塞原因和继续条件。
- 已修改文件及已完成工作，真实命令、退出码、测试结果、证据路径和未验证范围。
- 未完成事项、下一步、相关工作区变更。恢复时先复核实际文件和上次验证，再从当前阶段继续。

功能开发遵循[六步](../../standards/development-lifecycle.md)，其他任务使用[路由工作流](../workflows/task-routing.md)。[本次演练](upgrade-rehearsal.md)展示了如何留存两种业务判断。
