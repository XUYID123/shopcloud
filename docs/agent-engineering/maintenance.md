# 工程规范维护

规范版本 **1.1.0**。变更使用 Git 差异和下方变更记录追溯，继续建设时从[检查点](checkpoint.md)开始。

## 问题复盘

1. 记录可观察症状、受影响契约、阶段、重现条件、期望及证据。按 P0～P3 判断数据损失、越权、业务中断和回退紧急度。
2. 追溯这个需求是否读了适用 AGENTS 和 Docs，主技能是否正确路由，专项流程、规则、自动检查、测试或 ADR 是否缺失，工具能力是否限制验证。
3. 把修复放在能防止复发的最低层。核查同类调用、滚动升级、并发、重试、退回和失败恢复。实际执行回归，记录命令与最终结果。
4. 更新相关引用、版本与变更记录。涉及协议、数据库边界、中间件或其他重大架构决策时，新建 ADR 并链接被替代的决策。

| 根因 | 主要修复位置 |
|---|---|
| 项目事实或契约错误 | [Docs](../README.md)与实际入口 |
| 所有任务的工程行为遗漏 | [AGENTS.md](../../AGENTS.md)，专业细节链接至 Docs |
| 专业步骤遗漏或技能无法触发 | 对应 [SKILL.md](skills.md)，复核描述、实际发现和场景路由 |
| 编码规则缺失 | [工程规则](../standards/README.md)及专项知识页 |
| 可程序化检查缺失 | [Hooks、CI 和门禁](quality-gate.md)，模拟一次失败证明退出码有效 |
| 业务正确性、竞争或恢复缺口 | 业务最窄层级的可稳定复验测试。需要 Broker/MySQL 的用例留在隔离全量套件 |
| 决策与架构不一致 | [ADR](../decisions/README.md)，记录状态、背景、取舍、影响、验证和替代关系 |
| 工具验证能力受限 | 门禁说明、技术证据和明确的待验证项，保留实际运行结果 |

## 回归测试与规则维护

- 回归先做故障复现，再验证修复。并发用同步屏障或可控故障点，消息测试用独立 Topic/Group 与数据库，断言业务数据、去重收据和发布后的状态。
- 记录测试环境、命令、用例和复验结果。测试失败或缺结果在门禁中反映。兼容已有数据和消息格式，必要时覆盖旧 schema 或事件版本。
- AGENTS 保存全局决策和入口，技术细节使用单一权威文档。评审收敛重复规则，替代旧说明时保留历史状态；运行门禁并检查技能发现。
- 语义变更更新版本号。修订措辞/引用增补丁版本，兼容新增流程增次版本，改变强制流程或契约增主版本。每条变更记录带日期、范围、阶段或 ADR 和验证。
