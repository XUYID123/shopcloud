# Redis 与中间件选择

以 MySQL 和合适索引完成持久化与同步规则。有读负载、延迟、短时状态或跨实例原子操作证据时引入 Redis。

[Compose](../../shop-gateway/compose.yaml)中的 6380 为安全域（AOF/noeviction），关注内存写入拒绝与依赖故障时的安全策略。6381 为可丢缓存域（allkeys-lfu）。既有机制见[权限冷加载](../17-Redis权限冷加载与OpenFeign.md)、[同步缓存模板](../18-SafeCacheTemplate公共缓存组件.md)、[商品详情](../32-商品详情Redis缓存与失效.md)。

设计须列 Key、版本、数据结构/大小、TTL 和兼容序列化。合法性校验与短负缓存控制穿透，受限单键加载控制击穿，TTL 抖动与容量保护控制雪崩。监控热点请求、p99、淘汰与大 Key。回源设并发、超时和熔断预算。

以 DB 为准，可靠失效与业务同事务登记，提交后删除。处理旧值回填与删除竞争，约定陈旧窗口、版本保护、延期补偿及积压阈值。可回源数据有界降级，安全状态沿用拒绝策略。验证 TTL、回滚、并发、失败和恢复。异步机制见[消息](../messaging/README.md)。
