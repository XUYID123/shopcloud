# 商品分类创建接口

2026-10-30 安全迁移：本接口已接入网关逐请求内部 JWT 和下游统一验签。协议细节见 [24 文档](24-网关内部JWT与下游统一验签.md)，下文为当前实现。
日期：2026-10-30。本轮实现 shop-product 的第一个业务：POST /api/v1/admin/categories。数据库独立于 user，保留原 POM 继承和 application.properties 组织方式，采用父级已有的 MyBatis，不引入第二套 Mapper 框架。

创建后可通过已实现的 GET /api/v1/categories 查询启用分类，见 [分类列表查询](25-商品分类列表查询.md)。管理员分类详情 GET 仍待实现。

## 1. 接口契约

```http
POST http://localhost:8888/api/v1/admin/categories
Authorization: Bearer <accessToken>
Content-Type: application/json

{"name":"高筋面粉","sort":1,"enabled":true}
```

需要有效 JWT 和 product:write 权限。用户服务原 V2 已将该权限赋给 ADMIN 角色；公开注册仍只分配 USER，不自动提升现有用户权限。本次不新增角色管理接口。

name 去除首尾空白后长度 1～50；sort 为必填整数 0～10000；enabled 为必填布尔值。false 是合法输入，不允许省略。未知字段、额外 ID/角色、尾随 JSON、数字冒充名称、小数/字符串冒充排序均拒绝。

成功 HTTP 201，Location 为 `/api/v1/admin/categories/{categoryId}`，Result.data 为：

```json
{"categoryId":"1001","name":"高筋面粉","sort":1,"enabled":true}
```

Location 标识创建的资源，后台详情 GET 仍待后续实现。响应沿用 common Result，traceId 与 X-Trace-Id/X-Request-Id 一致。

| 情况 | HTTP / code |
|---|---|
| 参数非法 | 400 VALIDATION_ERROR |
| 网关缺少/无效 Token | 401，沿用网关认证业务码 |
| 下游缺少、过期、签名错误、错误受众或请求绑定的内部 JWT | 401 INVALID_INTERNAL_TOKEN |
| 下游收到匿名或权限查询用途的内部 JWT | 403 FORBIDDEN |
| 有身份但无商品管理权限 | 403 FORBIDDEN |
| 分类名重复，包括数据库排序规则判定的大小写重名 | 409 CATEGORY_NAME_EXISTS |
| 网关限流/防刷 | 原 429 语义 |
| 暂时性数据库/依赖故障 | 503 DEPENDENCY_UNAVAILABLE |
| SQL/程序错误 | 500 INTERNAL_ERROR，不泄露底层细节 |

没有给此接口增加短窗口 @Idempotent：稳定的业务唯一名称由数据库约束保证，重复创建始终获得明确的名称冲突，不被短窗口标记替换。写入超时可能已提交，不盲目重试 INSERT。

## 2. 启动与数据库

商品服务拥有 [compose.yaml](../shop-product/compose.yaml)，使用现有 MySQL 8.4.11 镜像，容器 mysql-product，开发端口 127.0.0.1:3308，库 flour_product，用户 shop_product，独立卷 mysql-product-data。开发口令通过 SHOP_PRODUCT_MYSQL_PASSWORD 覆盖，默认 shop_product_local_dev；生产应通过秘密注入配置。

IDE 使用 shop-product 模块目录作为工作目录启动，Boot Compose 自动启动商品数据库；从根目录运行时设置 SHOP_PRODUCT_COMPOSE_FILE 为该 Compose 的绝对路径，或先手工启动并关闭 Compose 自动管理：

```powershell
docker compose -f shop-product/compose.yaml up -d mysql-product
```

[application.properties](../shop-product/src/main/resources/application.properties) 已移除数据库/Flyway/MyBatis 的临时排除项，加入独立数据源、连接池上限/超时、Flyway 校验和 Mapper 路径。配置支持 SHOP_PRODUCT_MYSQL_HOST/PORT/USER/PASSWORD。Flyway 的 [V1__create_category.sql](../shop-product/src/main/resources/db/migration/V1__create_category.sql) 自动创建 category 表，含名称唯一约束、字段 CHECK、排序索引和毫秒时间。

本服务添加 Validation、Boot Compose 依赖并导入 common.GlobalExceptionHandler；Trace Filter 和其它 common 自动配置继续复用。

## 3. 网关鉴权及服务信任边界

流程：入口 WebFilter 清洗外部身份/内部凭据头 → 路由匹配 → Sentinel → Redis 防刷 → Access JWT 验签 → Redis RBAC 检查 product:write → 保存可信用户及同一权限快照摘要 → 路由改写/选址 → 网关签发内部 JWT → 商品服务公共过滤器验证 → 输入校验 → INSERT。

普通前端只提交 Authorization Bearer 和业务 JSON，**不需要 X-User-Id 或 X-Internal-Token**。网关通过普通 `shop-product-api` 路由转发，使用 [InternalTokenRelayFilter](../shop-gateway/src/main/java/org/spring/shopgateway/auth/InternalTokenRelayFilter.java) 统一签发内部 JWT；不再有分类专用 SetRequestHeader 或静态令牌配置。

内部 JWT 用网关独有私钥签名，含 userId、权限摘要、aud=shop-product、45 秒有效期和独立 jti，并绑定最终 POST 路径及查询串。商品服务只配置网关公钥，通过 common SPI 强制安装 [InternalAuthenticationFilter](../shop-common/src/main/java/org/spring/shopcommon/internalauth/InternalAuthenticationFilter.java)。全部验证通过后才信任载荷中的用户 ID，并重建 X-User-Id/Principal；外部伪造的用户、角色、权限头不作为身份来源。匿名和 permission-query 凭据不能创建分类。

旧 CategoryAccessConfiguration 已删除。Controller 不重复解析 JWT 或查询角色；权限摘要用于快照审计，不是在下游还原权限集合再次查询 RBAC。业务仍负责自身参数和唯一名称校验。

发现路由别名 `/shop-product/api/v1/admin/categories` 也经过相同鉴权，转发前签名绑定重写后的 `/api/v1/admin/categories`，不会因为路径前缀而验签失败。建议客户端统一使用上述标准路径。生产仍需服务端口隔离和 TLS，短期 JWT 的 jti 未增加消费去重状态。

RBAC 接口规则仍采用项目已有的 Redis 受控发布机制；准备好 6381 后，从根目录执行：

```powershell
./infra/security/Enable-CategoryRule.ps1
```

脚本读取当前 `shop:rbac:v1:rules`，保留已有规则，追加 POST 分类创建所需 product:write，再用版本 CAS 发布；不会清空或全量替换为只有商品规则。已有同名规则时提示审查，不擅自覆盖。规则更改不向普通用户授予权限；测试管理员需按既有受控方式分配 ADMIN。

## 4. 代码执行顺序

1. [CategoryController](../shop-product/src/main/java/org/spring/shopproduct/controller/CategoryController.java) 接收 @Valid DTO，只负责 HTTP 201/Location/Result。
2. [CategoryCreateRequest](../shop-product/src/main/java/org/spring/shopproduct/dto/CategoryCreateRequest.java) 绑定时去除名称首尾空白，再校验必填、长度、范围；[ProductJsonConfiguration](../shop-product/src/main/java/org/spring/shopproduct/web/ProductJsonConfiguration.java) 补充严格字符串类型校验。
3. [CategoryService](../shop-product/src/main/java/org/spring/shopproduct/service/CategoryService.java) 构造实体；单条 INSERT 为原子写入，无需先查重或引入长事务。
4. [CategoryMapper](../shop-product/src/main/java/org/spring/shopproduct/mapper/CategoryMapper.java) 通过 [XML](../shop-product/src/main/resources/mapper/CategoryMapper.xml) 的参数绑定写入，回填数据库生成的主键。
5. 此 INSERT 的唯一业务键只有名称；DuplicateKeyException 转为 CATEGORY_NAME_EXISTS，正常重名和并发重名统一 409。
6. 仅把已知暂时性/资源类数据库异常转为依赖不可用；SQL 程序错误保留未知异常语义，业务异常由 common 生成统一响应。
7. [CategoryVO](../shop-product/src/main/java/org/spring/shopproduct/vo/CategoryVO.java) 只输出契约内四个字段，ID 使用字符串。
