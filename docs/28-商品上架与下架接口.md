# 商品上架与下架接口

实现日期：2026-11-01。复用现有网关认证、product:write、内部 JWT、统一响应及 Trace ID。

## 请求约定

```http
PUT /api/v1/admin/products/10001/sale-status
Authorization: Bearer <Access Token>
Content-Type: application/json
```

```json
{"status":"ON_SALE","expectedVersion":1}
```

| 字段 | 含义与校验 |
|---|---|
| productId | 路径中的十进制正整数 ID，不超过 Long.MAX_VALUE |
| status | 必填枚举 ON_SALE（上架）或 OFF_SHELF（下架） |
| expectedVersion | 必填整数，1～9223372036854775806，来自当前商品 version；预留加一空间 |

仅接受上述两个请求体字段。缺失、非法枚举、字符串数字、小数版本、额外字段返回 400。

上架要求：商品存在、版本匹配、所属分类启用、至少有一个启用 SKU。库存尚未接入，上架不代表有库存，不会创建库存或 SKU。

下架要求：商品存在、版本匹配；即使分类禁用或没有启用 SKU，也允许停止销售。

成功返回 HTTP 200 和 ProductDetail：productId、categoryId、name、brand、glutenType、usageText、ingredients、storage、shelfLifeDays、imageUrl、status、version、skus。skus 包含按 ID 排序的全部规格（含禁用规格），每项遵守现有 Sku 契约，estimatedAvailable 仍为 null。响应体 traceId 与响应头一致。

每次成功提交版本加一，包含目标状态等于当前状态的操作。用旧版本重复请求返回 409，不重放首次成功结果；这不是结果重放型幂等接口。客户端收到网络异常时不要盲目重复提交，需刷新版本后确认状态；公开商品详情已在 29 文档实现，但不显示下架商品，管理端独立详情仍待实现，必要时通过管理工具核查数据库。

## 代码与事务流程

1. 网关入口处理 → 路由匹配 → Sentinel 容量保护 → 6380 IP 防刷 → JWT 认证 → 6381 RBAC product:write → 网关签发内部 JWT → 商品服务公共过滤器验签。
2. [ProductController](../shop-product/src/main/java/org/spring/shopproduct/controller/ProductController.java) 的 `changeSaleStatus` 验证 DTO，将路径 ID 和输入交给专门的销售用例。
3. [ProductSaleService](../shop-product/src/main/java/org/spring/shopproduct/service/ProductSaleService.java) 开启同库事务，检查 ID 并使用 `SELECT ... FOR UPDATE` 获取商品当前数据。商品不存在返回 404，版本不符返回 409。
4. 上架时通过已有 CategoryMapper 的 `FOR SHARE` 检查并锁住分类；读取当前所有 SKU 并加共享锁，无启用 SKU 返回 409。下架跳过分类条件，但仍查询规格用于响应。
5. 执行数据库原子更新：

```sql
UPDATE product_spu
SET status = :status, version = version + 1
WHERE id = :productId AND version = :expectedVersion;
```

6. 更新行数不为 1 返回 409；构建明确的响应字段，事务提交后才向调用方返回成功。

商品行锁保护跨记录的上架条件，并与新增 SKU 的“先锁 SPU，再写 SKU”协议协调；版本条件保护后台用户持有的旧版本，即使请求排队执行，旧版本也不能覆盖新操作。它们解决不同的问题。

锁只覆盖本地短事务，不持锁调用 Feign/Redis。后续实现 SKU 修改/删除、商品分类更换等操作时，应保持先锁 SPU 的一致顺序，避免反向持锁。分类和 SKU 在本事务提交后仍可被其他合法事务修改；将来实现禁用操作时，还需定义对已上架商品的影响，本接口不宣称永久维持上架条件。

复用 ProductCreatedVO 的 ProductDetail 结构，并把其 skus 从 List<Object> 收敛为 List<SkuCreatedVO>。新增 mapper 查询与 CAS 更新；本次没有改表结构，也不新增 Flyway 脚本。

## 错误与权限发布

| 场景 | HTTP / code |
|---|---|
| 参数或 ID 非法 | 400 / VALIDATION_ERROR |
| 缺少有效外部 Token | 401 / 现有网关认证码 |
| 缺少有效内部 JWT、用途或请求绑定不符 | 401 / INVALID_INTERNAL_TOKEN |
| 没有 product:write；内部匿名 JWT 访问 | 403 / FORBIDDEN |
| 商品不存在 | 404 / PRODUCT_NOT_FOUND |
| 上架时分类禁用 | 409 / CATEGORY_DISABLED |
| 上架时没有启用 SKU | 409 / PRODUCT_NOT_READY |
| 版本不匹配或 CAS 未命中 | 409 / STATE_CONFLICT |
| 容量/IP 额度拒绝 | 429 / 现有限流码 |
| 数据库暂时性连接/死锁等故障 | 503 / DEPENDENCY_UNAVAILABLE |

异常由公共处理器友好返回；依赖故障不自动重试写入，SQL 程序错误不被包装成 503。HTTP 响应中的数据库状态以提交时为准。

```powershell
./infra/security/Enable-ProductSaleRule.ps1
```

脚本保留其他规则，通过版本 CAS 向 6381 业务 Redis 追加 product-sale-status：PUT /api/v1/admin/products/*/sale-status，要求 product:write。同名规则存在时不覆盖。没有修改用户角色，不改变 6380/6381 职责、配置文件组织或 POM 结构。
